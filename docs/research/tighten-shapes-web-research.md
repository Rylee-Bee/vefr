# Web research for the "tighten the shapes" mission (digest, 2026-10-04)

Five read-only research workers (MiniMax, web search) answered five questions. This is my critical digest: what to **adopt**, **adapt** or **skip** for VEFR (Python stdlib-first, one offline HTML file, readable by people and agents, additive). Source links were reported by the workers; I opened only the two noted. Treat every row as a lead to confirm, not a fact.

## 1. Schema as data (for pass 2, item 3)
| Finding | Verdict | Why |
|---|---|---|
| Two-layer errors: a **stable code + path** (Pydantic `type` + `loc`) and free **prose**; tests pin the code and path, golden files hold the prose | **Adopt** | Matches our need that validator sentences stay byte-identical while the table is migrated: snapshot every existing sentence first (`tests/golden/`), then the schema renders them. |
| Put the human sentence on the rule itself (Smithy traits) so it travels with the schema | **Adopt** | One place to review wording. |
| One schema emits docs, a `*.schema.json` for editors/agents, and the validator (CUE, TypeSpec, Buf) | **Adopt** | The `*.schema.json` is cheap and makes agents better at writing packs. |
| `additionalProperties: false` on every object | **Already ours** | Blueprint's closed key sets; the table makes it universal. |
| Keep schema = shape, rules = tested code (msgspec); avoid a second programming language (Dhall's non-Turing-completeness) | **Adopt** | Cross-field rules (a lock names a declared item) stay as small tested functions beside the table. |
| Use `jsonschema`, Pydantic, or dataclass packs | **Skip** | New dependencies; the stdlib walker is about 100 lines and we need our own sentences. |
| Schema-registry compatibility tags (BACKWARD/FORWARD) | **Adapt later** | A line in the schema changelog and the existing "a pack without the block is unchanged" test is enough for now. |

## 2. Source to canonical with a lock (for the Blueprint pattern)
| Finding | Verdict | Why |
|---|---|---|
| Generate, commit both, and have CI run the generator then `git diff --exit-code`; never auto-commit the result | **Adopt** | We already fail on stale output in `vefr check`; add the CI shape for new generated surfaces. Verified the pattern in the player split (`tests/test_player_build.py`). |
| JSON Merge Patch (RFC 7396): small, `null` deletes, stdlib-implementable; arrays are replaced wholesale, use RFC 6902 ops when order matters | **Adopt** | Exactly the `pack(base, patch)` test helper. (RFC page opened: live.) |
| A digest/lock file over generated bytes (Terraform, `uv.lock`) | **Already ours** | `blueprint.lock.json` records the source hash and normalizer version. The worker wrongly said it was missing. |
| "Generated, do not edit" header | **Adapt** | JSON cannot hold comments and Blueprint's key sets are closed, so keep the marker in the lock and the stale check, not the file. |
| Jsonnet anecdote against committing generated output | **Skip** | Contradicts the rest; the evidence for committing is stronger. |

## 3. Level content as data (for things and places)
| Finding | Verdict | Why |
|---|---|---|
| LDtk: **definitions once, instances with typed fields** | **Adopt (already the shape)** | Blueprint families = definitions; instances = placements. Things and places extend it. |
| Dungeon Crawl vaults: a **legend line maps a glyph to a thing**, tags select where it may go | **Adopt** | The model for B2: the glyph is derived from a place record; tags like `guardian`, `key`, `door` feed placement. |
| Dormans: separate the **mission graph** (rooms, keys, locks) from the **spatial layout**; solvability is a reachability check on the graph | **Adopt** | That is our `locks.py` fixpoint; B3's "farthest room off the critical path" asks the graph. |
| Seeded placement stays stable only if randomness does not depend on call order | **Adopt, sharpened** | Derive each placement's seed from `hash(seed, record id)`, never from one shared stream, so adding a record does not move the others. |
| Flat, one-record-per-line shapes are the most LLM-readable | **Adopt** | Keep `places`/`things` flat; no nested graphs in the authored layer. |
| New `legend.json`, `definitions/entities.json` and `map.graph.json` files per pack | **Skip for now** | Three new files; ADR 0010 reuses `blueprint.json` and the contract. Revisit only if the contract gets crowded. |

## 4. Art ledger
| Finding | Verdict | Why |
|---|---|---|
| **Role -> rule table** (icon, creature, tile, sheet, ui part decide trim, padding, size, grid) | **Adopt** | Makes the flat-wall tile mistake impossible and shrinks the commands. |
| Provenance (prompt, model, seed) as a **sidecar**, never inside the image (WebP/AVIF re-saves drop chunks) | **Adopt** | The ledger entry is the sidecar; credits become three fields. |
| Credits **generated** from licence text, no local paths (REUSE/SPDX style) | **Adopt** | Fixes the temp-path leak found in Cottage's credits. |
| Encode WebP **once at import**, strip volatile metadata, never re-encode in the weave | **Adopt** | Same conclusion as the size pass: deterministic weaves. |
| Per-asset content hash in the ledger so drift breaks the build | **Adopt** | Cheap and catches silent re-cuts. |
| Sprite-sheet JSON (Aseprite / TexturePacker "JSON Hash") as the native atlas format | **Adapt** | We already ship `hero.sheet.json`; add an importer for the common format later, do not replace ours. |
| C2PA signing, DVC, git-lfs | **Skip** | Heavy; a sidecar and a hash do the job. |

## 5. Test kit and state
| Finding | Verdict | Why |
|---|---|---|
| Expose one **frozen, read-only state snapshot** instead of many globals; tests read it, not engine internals | **Adopt** | Finding 7 of the discovery record (`VEFR_STATE` facade). |
| A safe storage helper that falls back to memory; ban raw `localStorage` outside it with a lint | **Adopt (Python lint)** | 63 raw sites today. We have no ESLint; a small test that fails on raw use does the same. |
| Two-tier regression: a screenshot with a tolerance **plus** a state digest | **Adopt** | We have the weave digest and the bot; add a state digest to the bot report. |
| Playwright Clock for time control; one seeded PRNG | **Already mostly ours** | `vefr-save-seed` and the delve PRNG exist; use Clock in real-browser tests that need time. |
| "Use a real browser, not jsdom, by default" | **Skip** | jsdom with a canvas stub is what keeps 1,600 tests fast; real browsers stay for layout and a11y (`tests/browser`, the bot). |
| A `?test=1` bridge like AltTester | **Later** | Useful for the bot, but the facade covers most of it. |

## Corrections to my own earlier claims
None of the five changes the plan's direction. They sharpen it: stable codes with golden prose (schema), per-id hashed seeds (placement), role tables and generated credits (art), merge patches and CI diff checks (fixtures and generators), one frozen state object (tests).
