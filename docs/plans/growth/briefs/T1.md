# T1 — validator, load_pack, bake

Goal: a pack may carry an optional top-level `growth` block and enemies an optional `xp`. Read `design/growth.md` first (it is the spec). Acceptance: `bash docs/plans/growth/accept.sh tests/test_growth_validator.py` exits 0. Read that test file first: it pins every message substring and the exact bake strings.

Files you may edit: `src/vefr/maplab.py` (validation, beside `rules_errors` and the enemy `hp`/`atk` loop around line 1444), `src/vefr/world.py` (`load_pack` passes `growth` through ONLY when declared; update its docstring), `src/vefr/cli.py` (the `weave_html` bake near line 1858: bake `growth` as `{{growth_json}}`; a pack without it bakes literal `null`; make sure each enemy's `xp` is carried into `VEFR_ENEMIES`), and in `web/packaged.html` ONLY add the line `window.VEFR_GROWTH = {{growth_json}};` next to `window.VEFR_HERO = {{hero_json}};` (line ~537).

Rules (from the design, all must hold): `growth.mode` is `levels` or `practice`; the matching block must exist and the other must not. `levels.xp`: strictly rising whole numbers, first is 0, at most 20 entries. `levels.gain` and each `practice.<stat>.gain`: only `hp`/`atk` keys (for `gain`), whole 0..9. `practice` keys are only `hp`/`atk`; each has `by` in {strikes, hits-taken, consoles, hurls}, `every` whole 1..99, `gain` whole 0..9, `cap` whole >= 1. Enemy `xp`: whole >= 0, allowed only in `levels` mode (an error naming the enemy id and `xp` otherwise). Errors are plain sentences naming the field. A pack with no `growth` and no enemy `xp` must validate and bake as before (apart from the new `window.VEFR_GROWTH = null;` line).

Constraints: do not touch the tests or fixtures. No new dependencies. Match the surrounding code style. If the test contradicts this brief, stop and report.
