K1 is committed. Read `design/ui-skin.md` ("How it is drawn", "Rules") and `tests/test_skin_apply.py` + `tests/fixtures/skin_apply_harness.mjs` first.

In `web/packaged.html`, add ONE self-contained block (a function `applySkin()` called once at start, where the other start-up code runs): if `window.VEFR_SKIN` is a non-null object, create `<style id="vefr-skin-css">` in `<head>`, set its text from the baked skin, and add the class `has-skin` to `<body>`. With `VEFR_SKIN` null it does NOTHING (no element, no class: the game looks exactly as before).

The CSS (generated from the baked parts; use the player's real selectors, find them in the file's `<style>`): `.glass` and `#npc-box`, `#reader`, `#trade`, `#menu` panels use the `panel` part with `border-image: url(DATA) <slice> fill / <slice>px / 0 round` style nine-slice (set `background` to a flat colour taken from the panel's look so text stays on a calm ground); `.gbtn`, `.cta`, `.verb-row button` use `button` (and `:hover`, `:active`, `:disabled` use hover/pressed/disabled when the skin has them); `.hud-hp-bar` / `.hud-hp-fill` use `bar` frame/fill; `body.has-skin` gets `cursor: url(DATA) <hotspot x> <hotspot y>, auto` from `cursor` (and `a, button { cursor: url(hand...) ... }` when `hand` exists). Text colour on skinned panels comes from `ink.on_panel`. Missing parts are skipped, never an error.

Hard rules, pinned by the test: a skin NEVER removes the focus outline (do not write `outline: none`), buttons keep `min-height: 44px`, the whole skin CSS is wrapped so it does NOT apply under `prefers-contrast: more` or `forced-colors: active` (use `@media not all and (prefers-contrast: more)` style conditions, or put the skin CSS inside `@media (prefers-contrast: no-preference) and (not (forced-colors: active))`), and no picture is ever used as text (no `content: url(`).
