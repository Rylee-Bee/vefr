# S1 brief: a small synthesized sound set (foreman plan)

Objective: make `tests/test_sound.py` pass (read it first; frozen contract, never edit it; if a test contradicts this brief STOP and report).

One worker (tier `code`), four seams:
1. Validator: `maplab` checks an optional world.json `sound` block (object, exactly one key `theme`, value `"soft"`), wired into `maplab.validate` the way the `album`/`saves` blocks are. One plain sentence naming `sound`.
2. Bake: `cli.py` bakes it as `window.VEFR_SOUND_DEF` (the literal null when absent) next to `VEFR_ALBUM_DEF` in `web/packaged.html`'s template; a pack without `sound` weaves exactly as before.
3. Player (`web/packaged.html`): a function `soundCue(name)` that (a) does nothing when the pack has no sound or the player turned it off, (b) appends the name to `window.VEFR_SOUND.played` (keep the last 50) whenever the cue would sound, (c) plays a short synthesized tone with Web Audio if `AudioContext`/`webkitAudioContext` exists: create the context lazily on the first cue (a user gesture has happened by then), one table of cue definitions (frequency sweep, soft sine or triangle, 80-300 ms, peak gain at most 0.08, exponential release; "hit" a short low blip, "hurt" a lower blip, "defeat" two falling notes, "pickup" two rising notes, "door" a soft low sweep, "locked" two flat low notes, "level" three rising notes, "sticker" two bright notes, "end" a slow three-note chord), everything in try/catch so a missing or suspended AudioContext never throws. Call `soundCue` at the existing seams only: the hero's strike (`hit`), an enemy's strike (`hurt`), an enemy defeated (`defeat`), an item taken into the bag from the floor (`pickup`), a door or stair used (`door`), a locked transition refused (`locked`), a level gained (`level`), `albumEarn` (`sticker`), `openActEnd` (`end`). Never on a timer, never looping, never music. `window.VEFR_SOUND = {theme, on, played}` exists only when the pack opts in.
   The preference: `localStorage['vefr-sound-<world>']` = `"off"` when off (every access in try/catch); on by default.
4. Menu > Display: a checkbox `#sound-toggle` with a visible label "Sound", added only when the pack opts in, following the Display panel's existing controls and the skin/theme variables (no new colours; 44px target; keyboard focus visible). Changing it updates storage and `VEFR_SOUND.on`; turning it off stops recording cues.
Also: add `tests/test_sound.py` to `docs/features.json` (a new feature entry `sound`, status `built`, name "Small sounds", what "A few soft synthesized sounds for the moments of play, off with one switch.", detect: copy how another entry detects, docs `docs/guides/rulesets.md`; the features drift test must pass) and a short "Sound" section in `docs/guides/rulesets.md` (what a pack declares, the nine cues, the switch; six lines).

Constraints: stdlib only; neutral names; no audio files, no network; don't change other tests; acceptance `bash tests/run.sh tests/test_sound.py tests/test_album.py tests/test_complete_act.py tests/test_interact.py tests/test_features.py tests/test_overlay_interact.py tests/test_combat_loop.py --runxfail`. `git add` only files you changed; never commit PLAN.md or this brief. Run every worker in the foreground with a long timeout; never background, nohup or a monitor.
Final report: one JSON line `{"done": bool, "files": [...], "escalations": []}`.
