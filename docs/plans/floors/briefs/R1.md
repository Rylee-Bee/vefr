# R1 — the shared PRNG and generate_floor_v2 (Python)

Read `design/random-floors.md` ("The design" 1-3), `src/vefr/delve.py` (the existing `generate_floor` and its helpers) and `tests/test_delve_prng.py` + `tests/test_floor_v2.py` first.

Add to `src/vefr/delve.py` (do NOT change `generate_floor`: a test pins its exact output):
1. `prng(seed: str)` -> a function returning floats in [0, 1). It is xmur3 (hash the string by its UTF-16 CODE UNITS, as JavaScript's `charCodeAt` does; for characters above U+FFFF that means a surrogate pair) feeding mulberry32, with 32-bit integer maths (mask with `& 0xFFFFFFFF`; reproduce JavaScript's `Math.imul` as a 32-bit signed multiply, and `>>>` as an unsigned shift). The reference JavaScript (standard public-domain code) is:
```js
function xmur3(str){let h=1779033703^str.length;for(let i=0;i<str.length;i++){h=Math.imul(h^str.charCodeAt(i),3432918353);h=h<<13|h>>>19;}return function(){h=Math.imul(h^h>>>16,2246822507);h=Math.imul(h^h>>>13,3266489909);return(h^=h>>>16)>>>0;};}
function mulberry32(a){return function(){a|=0;a=a+0x6D2B79F5|0;let t=Math.imul(a^a>>>15,1|a);t=t+Math.imul(t^t>>>7,61|t)^t;return((t^t>>>14)>>>0)/4294967296;};}
// prng(seed) = mulberry32(xmur3(seed)())
```
`tests/test_delve_prng.py` pins the first six outputs for five seeds, computed by that reference.
2. `generate_floor_v2(seed, width=30, height=20, rooms=8) -> list[str]`: the same SHAPE as `generate_floor` (rooms joined by corridors, a solid wall border, `u` and `d` stairs at least `MIN_STAIR_DISTANCE` apart when the layout allows, everything connected, same ValueErrors) but drawn ONLY from `prng(seed)`. You may reuse the existing pure helpers (`_center`, `_overlaps`, `_carve_room`, `_carve_h`, `_carve_v`) but NOT `random.Random`, `random.shuffle`, `random.choice`, sets or dict ordering for anything that affects the result. Draw integers as `int(rng() * n)` (a JavaScript twin will use `Math.floor(rng() * n)` and must get identical numbers). Where you need a shuffle, write Fisher-Yates with `prng` draws; where you sort, give an explicit tiebreaker. Keep the maths in whole numbers.
3. Write the algorithm as a short numbered comment above the function: the exact order of draws, step by step. A second worker will port it to JavaScript from that comment and your code, line for line, and a test replays 60 floors through both and demands identical rows. Anything vague in the comment becomes a parity failure, so be exact (loops, ranges inclusive or exclusive, tie-breaks).

Constraints: standard library only; do not touch tests or fixtures. If a test contradicts this brief, stop and report.
