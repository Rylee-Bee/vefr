A world in the studio is a folder of files. A game is something you
can hand to a friend. Turning one into the other is the last step.

* * *

At the Desk there's a button: **Make shareable file**. The studio calls
this *weaving*. It gathers your world's map, people, words, and pictures
and stitches them into one web page that plays by itself.

Programmers call this a *build*. The finished file is an *artifact*.
Handing it to people is a *release*, or *shipping*.

* * *

A game made this way needs no studio, no internet, and no helper to
play. If a character's model isn't there, their hand-written lines
speak instead. Everything the game needs is inside the one file.

Programmers call that *self-contained*. You can copy it anywhere and
it still works.

* * *

Every release gets a number, like 2.1.0. The first number goes up for
big changes, the middle for new things, the last for fixes. That's
*semantic versioning*. The list of what changed is the *changelog*.

* * *

Before each studio release, a robot checks everything: the tests, the
pictures, the reading rules for screen readers. Checks that run
themselves on every change are *continuous integration*, or *CI*.

* * *

**Try it.** At the Desk, press **Make shareable file**. Open the file it
makes in your browser, with the studio closed.

That's your world, shipped. Send it to someone.
